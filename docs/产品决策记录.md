## 产品定位

VoiceCanvas 是一个面向内容创作者的纯语音创作草图工具。用户可以通过说话创建、修改、组织和导出单张场景草图或短视频分镜草稿。

项目重点不是生成一张不可编辑的精美图片，而是帮助用户把创意快速变成可沟通、可修改、可导出的视觉草稿。

## 目标用户

优先服务短视频内容创作者，包括但不限于：

- 带货视频创作者
- 探店视频创作者
- 知识教程类创作者
- 需要快速表达画面想法的策划、运营、编导或产品人员

## 核心商业价值

传统文生图工具擅长生成单张结果图，但不擅长持续、精确、低成本地修改画面。VoiceCanvas 的价值在于：

- 用语音降低创作门槛，用户不需要掌握 PS、Figma 或复杂 prompt。
- 用结构化画布保留可编辑性，支持移动、缩放、删除、改文字、改镜头。
- 用分镜组织能力服务短视频创作，而不是只生成单张图片。
- 用元素级生成或占位策略补足素材缺口，避免整图反复生成带来的不可控和高成本。

一句话差异化：

> VoiceCanvas 不是 Voice-to-Image，而是 Voice-to-Editable-Storyboard。

## 成功指标

### 用户价值指标

MVP 是否成功，首先看用户能否只靠语音完成一次完整创作闭环：

- 从一句创意创建出单张草图或多镜头分镜。
- 能继续用语音添加、修改、删除元素。
- 能通过箭头、连接线和画面说明表达元素关系。
- 能通过画面说明判断 AI 是否理解了自己的需求。
- 能撤销错误操作，并导出可沟通的结果。

核心体验目标：

> 用户在不使用鼠标和键盘进行核心创作操作的情况下，能在 3 分钟内完成一组可展示、可修改、可导出的创作草稿。

### 演示成功指标

Demo 至少应稳定展示以下能力：

- 语音创建一个三镜头带货分镜。
- 每个镜头生成画面草图、字幕/旁白、镜头说明和画面说明。
- 语音添加元素，例如商品、人物、标签、文字、箭头或连接线。
- 语音修改指定元素，例如移动、缩放、改文字、改颜色。
- 语音管理镜头，例如新增、删除或切换镜头。
- 语音撤销一次错误操作。
- 导出图片和 JSON 项目数据。

### 解析与执行指标

为保证系统不是只能跑固定 Demo，MVP 需要满足以下可测试指标：

- 覆盖至少 9 类指令：创建、镜头管理、添加元素、修改元素、删除元素、布局/图层、风格、历史控制、导出。
- 每类指令至少准备 3 条测试语料。
- 高频指令解析成功率目标不低于 80%。
- 对指代不明确的指令，例如“把它放大一点”，能基于最近元素处理，或进入确认流程。
- 未知元素不能直接失败，至少生成语义占位元素。

### 工程质量指标

为匹配比赛评审中的“开发过程与质量”，MVP 需要满足以下工程指标：

- 语音解析、画布状态、命令执行、历史记录、导出模块保持解耦。
- 每个核心模块都有可运行测试。
- 画布状态可以导出为 JSON，并能用于复现当前草图。
- 普通编辑操作不依赖生图模型，避免每次修改都产生高成本调用。
- 失败或低置信度解析有明确降级策略，而不是静默失败。

### 成本与性能指标

MVP 阶段的成本控制目标：

- 移动、缩放、改文字、改颜色、撤销、重做等普通操作不调用大模型或生图模型。
- 未知元素优先使用语义占位；如接入生图，只按元素级生成，不整图重生成。
- 高频规则类指令优先走规则解析，复杂创作类指令再调用 AI。
- 常见语音指令从识别完成到画布更新，目标响应在 1 秒内；复杂生成类指令允许异步完成。

## 关键产品决策

### 决策 1：选择“AI 语音绘图工具”作为参赛题目

结论：选择题目二“AI 语音绘图工具”。

理由：

- 72 小时内更容易做出完整闭环。
- 语音指令解析、画布状态、撤销重做、导出等模块更容易测试。
- 更容易体现架构清晰度、可扩展性和工程质量。

### 决策 2：主场景聚焦内容创作者，但不限制用户自由创作

结论：产品重点优化短视频分镜草图，但基础能力必须支持自由语音绘图。

理由：

- 只做带货或固定模板会显得产品过窄。
- 题目本质要求是纯语音绘图工具，不能只做分镜模板生成器。
- 用户可能只是想画一个单张草图，例如“画一棵树”“画一个桌子后面有恐龙”。

影响：

- 系统需要同时支持自由画布模式和分镜模式。
- 分镜本质上可以理解为多个小画布的集合。

### 决策 3：采用“结构化画布 + 元素级生成/降级”的方案

结论：画布内容应由结构化元素组成，而不是一整张不可编辑图片。

每个元素至少包含：

```ts
{
  id: string;
  name: string;
  type: "shape" | "text" | "template" | "generated_asset";
  x: number;
  y: number;
  width: number;
  height: number;
  zIndex: number;
}
```

理由：

- 可以精确支持语音修改，例如“把恐龙放大”“删除优惠标签”“把标题移到右上角”。
- 可以支持撤销、重做和 JSON 导出。
- 可以降低成本，普通编辑不需要重新调用生成模型。

### 决策 4：未知元素不直接失败，采用占位或元素级生成

结论：用户说出系统未内置的对象时，MVP 不能报错中断创作。

处理策略：

- MVP 保底：生成语义占位元素。
- 增强实现：调用生图模型生成透明背景素材。
- 所有未知元素生成后仍进入统一画布图层系统。

示例：

- 用户说“画一只恐龙”。
- 系统可以生成“恐龙”占位元素，或生成一个独立恐龙素材。
- 后续仍可语音移动、缩放、删除该元素。

### 决策 5：不承诺任意对象的无限内部编辑

结论：复杂对象内部编辑采用分层模板、整体替换或局部再生成，而不是临时拆成一堆不协调素材。

理由：

- 动态分别生成“杯子、奶茶液体、珍珠、吸管”再拼接，容易出现透视、光照、比例和风格不一致。
- 对高频商业元素，可以提前准备协调的分层模板。
- 对低频复杂元素，作为整体素材处理更稳定。

处理策略：

- 高频元素：使用预制分层模板，例如珍珠奶茶、手机、耳机、商品卡片。
- 非模板元素：整体生成或语义占位。
- 内部修改：模板元素改子层；非模板元素通过重新生成、局部修图或替换降级处理。

### 决策 6：支持简单图层和遮挡关系，但不在 MVP 做复杂图形引擎

结论：MVP 支持基础空间关系，包括前后、左右、上下、居中、置顶、上一层、下一层。

理由：

- “恐龙在桌子后面”这类表达需要最基本的图层和遮挡能力。
- 完整 Scene Graph、遮罩、约束布局可以作为未来扩展。

MVP 实现方式：

- 使用 `zIndex` 控制前后。
- 使用坐标和尺寸控制布局。
- 必要时用简单矩形遮挡模拟前景遮挡后景。

### 决策 7：支持关系表达和画面说明

结论：MVP 应支持箭头、连接线和画面说明，让用户不仅能画出元素，还能表达元素之间的关系，并检查 AI 是否理解了自己的需求。

理由：

- 内容创作者的草图不只是视觉摆放，还需要表达“谁指向谁”“什么导致什么”“这个区域是什么意思”。
- 箭头和连接线是正常画图软件的基础能力，也是分镜、流程、构图说明中高频使用的表达方式。
- 每个画布或镜头旁边保留一段 AI 生成的画面说明，可以帮助用户快速判断系统是否理解了指令。

影响：

- 元素类型需要增加 `arrow` 和 `connector`。
- 每个画布或镜头需要保存 `description` 字段。
- 修改镜头说明和修改画面说明应作为 MVP 支持的语音指令。

## MVP 功能清单

### 1. 创建项目/分镜

MVP：

- 创建自由画布
- 创建分镜
- 根据主题生成初始内容

### 2. 画布/镜头管理

MVP：

- 新增镜头/画布
- 删除镜头
- 切换镜头

加分项：

- 复制镜头
- 排序镜头

### 3. 添加元素

MVP：

- 添加人物
- 添加商品
- 添加文字
- 添加标签
- 添加箭头
- 添加连接线
- 添加背景
- 添加未知元素

说明：未知元素在 MVP 中至少以语义占位形式出现；如果进度允许，再接入元素级生成。

### 4. 修改元素

MVP：

- 改文字
- 改箭头/连接线文字
- 改颜色
- 改大小
- 改位置
- 改时长
- 改镜头说明
- 改画面说明

### 5. 删除元素

MVP：

- 删除元素
- 删除镜头

加分项：

- 删除模板子层，例如“删掉珍珠”

### 6. 调整布局/图层

MVP：

- 放到左边
- 放到右下角
- 居中
- 上一层
- 下一层
- 置顶

加分项：

- 放到桌子后面
- 前后遮挡关系
- 更复杂的空间关系

### 7. 风格调整

MVP：

- 清爽
- 科技
- 促销

加分项：

- 温暖
- 极简
- 自定义风格，例如“小红书风格”“赛博朋克风格”

说明：风格调整优先修改结构化样式变量，不重新生成整张图。

### 8. 历史控制

MVP：

- 撤销
- 重做
- 清空

### 9. 导出

MVP：

- 导出图片
- 导出 JSON

加分项：

- 导出分镜长图

## 明确不做

MVP 不做以下内容：

- 不做真正视频生成
- 不做完整视频剪辑器
- 不做 PS/Figma 级精细编辑
- 不承诺任意复杂物体的内部拆解
- 不承诺所有自然语言都能完美理解
- 不把整张图生图作为核心方案
- 不做复杂骨骼动画或完整时间轴

## 主演示流程

优先演示带货短视频分镜，但产品能力不限制在带货模板。

建议演示链路：

1. 用户说：“创建一个三镜头的珍珠奶茶带货分镜，主打低糖和新品上市。”
2. 系统生成三个镜头：痛点/钩子、产品特写、优惠转化。
3. 系统在每个镜头旁边生成画面说明，复述 AI 对画面和意图的理解。
4. 用户说：“把第二镜头里的珍珠删掉，改成低糖奶茶。”
5. 系统隐藏珍珠层，或替换为无珍珠奶茶模板。
6. 用户说：“给第二镜头加一个箭头，指向低糖标签，写上核心卖点。”
7. 用户说：“第三镜头加一个限时优惠标签，放到右下角。”
8. 用户说：“整体改成清爽绿色风格。”
9. 用户说：“撤销上一步。”
10. 用户说：“导出分镜。”
