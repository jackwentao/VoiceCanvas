# 自主分镜 Agent 真实验收

使用现有 CommandCode 兼容端点与 `deepseek/deepseek-v4.1-flash`，原生 tools，`reasoning_effort=off`。没有固定分镜模板或正则路由。API 与页面分别提交同一份真实业务需求：咖啡店老板给摄影师制作15秒三镜头分镜，包含雨中进店、接杯、优惠近景。原文、工具选择、工具结果和最终项目见 `api-run.json`、`page-run.json`，没有密钥。

## 实际结果

两次均自主建立3个独立镜头，复用初始空镜头，各5秒，保存景别、拍摄说明与共用角色设定，每镜单独生成 SVG。第一次模型选择读取→共同设定→创建→两镜并发绘制→第三镜绘制→交付核对；第二次还自行选择了源码检查工具。这里是实际调用记录，不是程序规定的顺序。离线另覆盖已有画面直接编辑，无创建或规划步骤。

原始产物为 `api-shot-1/2/3.svg`、`page-shot-1/2/3.svg`。两次首次保存画面分别在任务开始47.5秒、48.5秒左右；全部3张保存分别76.0秒、79.2秒，见 `timings.json`，不包含最后总结完成耗时。三镜耗时不能和单镜16.7/20.8秒直接比较；新增了真实拆镜和管理决策，同时不同镜头最多两路绘制。模型推理已关闭，后续提速应关注决策轮数和绘图输出，而不是删除必要分镜。

页面测试在第三镜绘制时刷新，恢复同一任务 `run_c1ef2b0b01364f55`，最终只有3次 draw_shot、每镜1个版本，无重复绘制。

随后通过同一输入框提交「把第二个镜头移到最后，并把优惠特写镜头改名为雨天优惠，保留现有画面」；模型调用移动和改名，没有调用绘图，3镜画面版本仍为1，见 `manage-run.json`。模型还指出原拍摄说明内时间码未随顺序变化更新，未掩盖该未完成项。

再提交整组 SVG 导出，Agent 选择 export_shots，按当前顺序产生3个浏览器下载动作，见 `export-run.json`。页面执行下载请求；这里仅确认已向浏览器发起，不把浏览器请求冒充用户已保存文件。

## 看图后的判断

分镜执行闭环通过，关键动作质量未通过。雨中女孩仍像站在店外，未清楚表现推门进入；递杯镜头手部与杯子关系不够准确，不能把双手相接视作双方同握杯子。产品近景中的「雨天咖啡买一送一」在页面清晰可读。角色通过文本共同设定约束，仍无可靠视觉一致性保证。

Agent 当前没有看图工具，源码检查不代表动作验收。两次均以 needs_input 保留人工验收项。任务系统会核对真实数量、实际画面和时长，但不能凭 SVG 合法证明动作画对；没有宣称这已达到最终生产画质。
