# 输入无效果排查与验证

2026-11-17 当前页面误连到研发回放服务 8014，该服务修改时只执行固定字符串替换，不能响应任意绘图要求。已将实际打开的工作台切至默认 8000 的 `voicecanvas.api.main:app`，继续使用原 SQLite 数据库保留项目。测试后端 `browser_fixture:app` 和历史研究目录的 `preview_app:app` 只用于固定响应验证，不能充当产品绘图服务。

## 启动与网络

按 [单镜头创作](单镜头创作.md) 配置后端模型并启动 8000，再访问 `http://127.0.0.1:4178/workspace.html`。检查 URL 的 `apiBaseUrl` 是否指向自己实际启动的模型服务；默认无需此参数。密钥只在后端，不放进页面、URL 或 Git。

本机 Python/httpx 经 IPv4 访问模型端点时出现 `SSL: UNEXPECTED_EOF_WHILE_READING`，IPv6 下匿名读取 `/models` 返回 200。如实际环境也验证了相同情况，可在后端启动前设置：

```powershell
$env:VOICECANVAS_SHOT_LOCAL_ADDRESS="::"
```

这会将绘图请求绑定 IPv6 本地地址，不修改系统网络或关闭 TLS 证书校验，不自动付费重试。没有 IPv6 网络时不要设置。每次修改后重启后端；错误密钥、模型名、余额或网络问题仍会明确失败，不返回固定画面。

## 交互反馈

- Enter 或发送按钮提交，Shift+Enter 换行；中文输入法正在选字时 Enter 不提交。
- 模型生成期间显示“正在绘制画面”和已等待秒数，控件锁定防止重复调用。
- 失败在输入框上方和错误栏显示原因，保留当前画面与输入；不再停留在“正在完成指令”。
- 模型返回与原 SVG 完全相同的内容时提示“没有变化”，不误报改画成功。此比较只检测源码完全相同，不代表自动评估画面是否符合需求。

## 真实模型验收结果

2026-11-17 使用真实 `deepseek/deepseek-v4.1-flash`、上述端点及 IPv6 连接，在实际打开的工作台用输入框完成：

1. 描述黄昏车站、黄外套女孩、长椅、红伞和列车，模型调用 100.69 秒返回完整 SVG，页面保存为版本 1。
2. 输入“只把雨伞的红色伞面改成蓝色，伞杆、女孩、长椅、火车和背景保持不变”，11.67 秒完成源码补丁，预览显示蓝伞并保存为版本 2。
3. 刷新同一 `board` 页面，蓝伞画面和两个版本仍在；原先包含 5 个镜头的项目继续保留在同一数据库。

生成与修改分别记录 16912、7227 个供应商 total_tokens，不含此前失败请求。首次较复杂画面的真实生成曾因 SVG id 重复或无效被拒绝；随后增加输出格式约束再完成上述验收。本次证明输入、模型调用、保存与继续修改连通，不保证模型每次输出都通过校验或符合画面要求。画面仍可看到手臂比例问题，不将联通成功当作画质合格。

自动验证实际结果：前端原型契约及 33 项单元测试通过；后端绘图/分镜 84 项、文字/回放 24 项通过，相关文件 Ruff 和 JavaScript 语法检查通过。保留现有 Starlette/httpx 弃用提示。
