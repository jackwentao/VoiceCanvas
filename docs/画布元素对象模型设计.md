# 画布元素对象模型设计

> 本文用于重新定义 VoiceCanvas 的画布元素数据契约。目标是让 AI、后端命令执行器、前端渲染器和后续素材生成模块使用同一套语义清晰、可扩展、可测试的对象模型。

## 现状问题

当前模型主要描述元素的外框和位置，例如 `x`、`y`、`width`、`height`、`zIndex`，但缺少以下关键信息：

- 元素真正显示什么：文本内容、图片资源、人物姿态、图形内部标签、连接线文案等。
- 元素长什么样：字体、填充、描边、阴影、圆角、滤镜、图片裁剪方式、线帽、箭头头部等。
- 元素如何参与布局：自身锚点、连接点、吸附规则、约束、和其他元素的语义关系。
- 类型专属数据：文字需要排版字段，连接线需要路径和端点，生成素材需要提示词和生成状态，人物需要角色与姿态。

因此前端只能把所有元素粗略画成矩形 DOM。连接线目前也只是一个有背景色的横条，无法根据目标元素边缘、锚点和箭头头部计算真实路径，所以箭头指向不准、视觉效果生硬。

## 设计原则

- 公共属性只表达所有元素共有的身份、布局和元信息。
- 内容属性描述“显示什么”，样式属性描述“长什么样”，类型专属属性描述“这个类型独有的行为”。
- 连接关系用引用和锚点表达，不直接依赖手填的线段外框。
- 渲染器只根据确定数据绘制，不靠猜测。
- 后端 Pydantic 模型和前端 TypeScript 类型保持同构，新增元素类型时不影响已有类型。

## 推荐元素分类

MVP 建议从以下元素类型开始：

| 类型 | 用途 | 关键数据 |
| --- | --- | --- |
| `text` | 独立文字、标题、标签文字 | 文本内容、排版、字体样式 |
| `shape` | 几何图形、容器、徽章、按钮底形 | 图形类型、填充、描边、内部标签 |
| `connector` | 连接线、箭头、流程指向 | 起点、终点、路径、箭头样式 |
| `image` | 已有图片资源 | assetId、url、裁剪和适配方式 |
| `generated_asset` | AI 生成素材，如人物、产品图、背景 | 提示词、生成状态、资源引用、素材语义 |
| `group` | 组合元素 | 子元素引用、组合布局约束 |
| `unknown` | 暂不支持或低置信度对象 | 占位说明、降级样式 |

说明：人物不建议直接做成 `shape`。人物更适合先归入 `generated_asset`，并通过 `assetKind: "character"`、角色、姿态、表情等字段表达。这样后续可以从占位框平滑升级成真实生成素材。

## 分层模型

### 公共属性

```ts
type CanvasElement =
  | TextElement
  | ShapeElement
  | ConnectorElement
  | ImageElement
  | GeneratedAssetElement
  | GroupElement
  | UnknownElement;

type BaseElement = {
  id: ElementId;
  type: CanvasElementType;
  name?: string;
  role?: "content" | "decoration" | "control" | "annotation" | "background";
  transform: ElementTransform;
  layer: ElementLayer;
  interaction?: ElementInteraction;
  semantic?: ElementSemantic;
  metadata?: Record<string, unknown>;
  createdAt: ISODateTime;
  updatedAt: ISODateTime;
};

type ElementTransform = {
  x: number;
  y: number;
  width: number;
  height: number;
  rotation?: number;
  opacity?: number;
  visible?: boolean;
  locked?: boolean;
};

type ElementLayer = {
  zIndex: number;
  blendMode?: "normal" | "multiply" | "screen" | "overlay";
};

type ElementSemantic = {
  tags?: string[];
  description?: string;
  referNames?: string[];
};

type ElementInteraction = {
  selectable?: boolean;
  draggable?: boolean;
  resizable?: boolean;
  connectable?: boolean;
};
```

为什么把 `transform` 和 `layer` 从顶层拆出来：后续局部更新、历史记录、布局算法和渲染器都可以只处理对应块，避免一个元素对象越来越扁平、越来越难维护。

### 文字元素

```ts
type TextElement = BaseElement & {
  type: "text";
  content: {
    text: string;
    placeholder?: string;
  };
  style: TextStyle;
  boxStyle?: BoxStyle;
};

type TextStyle = {
  fontFamily?: string;
  fontSize: number;
  fontWeight?: "normal" | "medium" | "semibold" | "bold";
  fontStyle?: "normal" | "italic";
  color: string;
  align?: "left" | "center" | "right";
  verticalAlign?: "top" | "middle" | "bottom";
  lineHeight?: number;
  letterSpacing?: number;
  maxLines?: number;
  overflow?: "clip" | "ellipsis" | "shrink";
};
```

文字的底色不应混在 `TextStyle` 里，应该放到 `boxStyle`，否则“文字颜色”和“文字容器样式”会混在一起。

### 图形元素

```ts
type ShapeElement = BaseElement & {
  type: "shape";
  content?: {
    label?: string;
    icon?: string;
  };
  shape: {
    kind:
      | "rectangle"
      | "rounded_rectangle"
      | "ellipse"
      | "circle"
      | "diamond"
      | "triangle"
      | "pill"
      | "badge";
    cornerRadius?: number;
  };
  style: ShapeStyle;
};

type ShapeStyle = {
  fill?: Paint;
  stroke?: StrokeStyle;
  shadow?: ShadowStyle;
};
```

图形不是文字，也不是图片。它可以带内部标签，但标签应是 `content.label`，不应该依赖 `name`。`name` 是给 AI、历史记录和图层面板读的，不一定要显示在画布上。

### 连接线元素

```ts
type ConnectorElement = BaseElement & {
  type: "connector";
  content?: {
    label?: string;
    labelPosition?: "start" | "middle" | "end";
  };
  connector: {
    kind: "line" | "elbow" | "curve";
    from: ConnectorEndpoint;
    to: ConnectorEndpoint;
    waypoints?: Point[];
    routing?: "straight" | "orthogonal" | "bezier" | "smart";
  };
  style: ConnectorStyle;
};

type ConnectorEndpoint = {
  target:
    | { type: "element"; elementId: ElementId }
    | { type: "point"; point: Point };
  anchor?: AnchorSpec;
  offset?: Point;
};

type AnchorSpec =
  | "top"
  | "right"
  | "bottom"
  | "left"
  | "center"
  | "auto"
  | {
      side: "top" | "right" | "bottom" | "left";
      ratio: number;
    };

type ConnectorStyle = {
  stroke: StrokeStyle;
  markerStart?: MarkerStyle;
  markerEnd?: MarkerStyle;
  lineCap?: "butt" | "round" | "square";
  lineJoin?: "miter" | "round" | "bevel";
};
```

连接线最重要的是 `from` 和 `to`。它的 `transform` 只能作为缓存边界或选择框，不能作为真实端点来源。真实绘制时应根据目标元素的边界盒和锚点计算路径。

### 图片元素

```ts
type ImageElement = BaseElement & {
  type: "image";
  content: {
    assetId?: AssetId;
    url?: string;
    alt?: string;
  };
  image: {
    fit: "cover" | "contain" | "stretch" | "none";
    focalPoint?: Point;
    crop?: Insets;
  };
  style?: ImageStyle;
};
```

图片元素表达已有素材，通常资源已确定。它和生成素材的区别在于，图片只关心如何显示，生成素材还关心如何产生、当前是否已完成。

### 生成素材元素

```ts
type GeneratedAssetElement = BaseElement & {
  type: "generated_asset";
  content: {
    assetId?: AssetId;
    url?: string;
    alt?: string;
  };
  asset: {
    kind: "character" | "product" | "background" | "icon" | "illustration" | "texture";
    status: "pending" | "generating" | "ready" | "failed";
    prompt: string;
    negativePrompt?: string;
    provider?: "mock" | "qiniu" | "openai" | "local";
    generationId?: string;
    sourceElementId?: ElementId;
  };
  subject?: GeneratedSubject;
  image: {
    fit: "cover" | "contain" | "stretch" | "none";
    focalPoint?: Point;
    crop?: Insets;
  };
  style?: ImageStyle;
  placeholderStyle?: ShapeStyle;
};

type GeneratedSubject = {
  character?: {
    role?: string;
    pose?: string;
    expression?: string;
    clothing?: string;
  };
  product?: {
    category?: string;
    brand?: string;
    keyFeatures?: string[];
  };
};
```

人物、产品、背景都可以先用 `generated_asset` 表示。这样 AI 生成前可以显示占位，生成完成后只补充 `assetId` 和 `url`，不需要把元素类型从 `unknown` 改来改去。

### 组合元素

```ts
type GroupElement = BaseElement & {
  type: "group";
  children: ElementId[];
  group: {
    clipContent?: boolean;
    layout?: "free" | "horizontal" | "vertical" | "grid";
  };
};
```

组合元素只引用子元素，不直接复制子元素数据。这样移动组合时，可以通过布局命令统一更新子元素，历史记录也更容易追踪。

### 通用样式基础类型

```ts
type Paint =
  | { type: "solid"; color: string }
  | { type: "linear_gradient"; from: string; to: string; angle?: number }
  | { type: "image"; assetId: AssetId; opacity?: number };

type StrokeStyle = {
  color: string;
  width: number;
  dash?: number[];
  opacity?: number;
};

type MarkerStyle = {
  type: "arrow" | "triangle" | "dot" | "none";
  size?: number;
  fill?: string;
};

type BoxStyle = {
  fill?: Paint;
  stroke?: StrokeStyle;
  radius?: number;
  padding?: Insets;
  shadow?: ShadowStyle;
};

type ImageStyle = {
  radius?: number;
  stroke?: StrokeStyle;
  shadow?: ShadowStyle;
  filter?: {
    blur?: number;
    brightness?: number;
    contrast?: number;
    saturate?: number;
  };
};

type ShadowStyle = {
  color: string;
  blur: number;
  offsetX: number;
  offsetY: number;
  opacity?: number;
};

type Point = {
  x: number;
  y: number;
};

type Insets = {
  top: number;
  right: number;
  bottom: number;
  left: number;
};
```

## 箭头精准性的关键设计

箭头不应该用 `x/y/width/height` 直接画一条横线。正确流程是：

1. 根据 `connector.from.target` 找到起点元素。
2. 根据 `connector.to.target` 找到终点元素。
3. 读取两个元素的 `transform`，得到边界盒。
4. 根据 `anchor` 计算真实端点，例如右侧中点、左侧中点、顶部 30% 等。
5. 根据 `routing` 生成 SVG path。
6. 根据 `markerEnd` 绘制箭头头部。
7. 根据 `labelPosition` 把连接线文案放在路径中点或端点附近。

前端推荐用 SVG 单独渲染连接层：

- 普通元素继续用 HTML 或 SVG 渲染。
- 连接线统一放进 `<svg class="connector-layer">`。
- 每条连接线使用 `<path>` 和 `<marker>`。
- 元素移动后，根据元素 ID 重新计算 path。

这样箭头可以真正指向目标元素边缘，而不是指向一个手填矩形。

## 为什么现在前端画得丑

主要原因不是单纯 CSS 丑，而是数据不足导致渲染器只能降级：

- `unknown` 人物只有一个矩形占位，没有角色、姿态、素材状态，所以前端只能画框。
- `shape` 没有内部内容模型，前端把 `name` 显示出来，导致图层名称变成画面内容。
- `style` 是松散字典，没有稳定的 fill、stroke、shadow、text box 语义，视觉默认值很粗糙。
- `connector` 虽然有 `from` 和 `to`，但前端没有用它们计算端点，只按 `x/y/width` 画横条。
- 前端使用 DOM button 承载所有元素，天然带有按钮语义和布局限制，不适合作为高质量画布渲染层。
- 缺少设计 token，例如字号层级、圆角层级、阴影层级、颜色用途，导致每个元素的视觉关系不统一。

对象定义不是唯一问题，但它是根问题之一。数据模型没有说清楚“这是什么、显示什么、怎么显示、和谁连接”，前端就很难画得专业。

## 渲染架构建议

前端建议拆成四层：

```text
CanvasRenderer
├─ BackgroundLayer
├─ ElementLayer
│  ├─ TextRenderer
│  ├─ ShapeRenderer
│  ├─ ImageRenderer
│  └─ GeneratedAssetRenderer
├─ ConnectorLayer
│  └─ ConnectorRenderer
└─ SelectionLayer
   ├─ BoundingBox
   ├─ ResizeHandles
   └─ AnchorHandles
```

其中 `ConnectorLayer` 应依赖元素布局索引：

```ts
type ElementLayoutIndex = Record<ElementId, {
  id: ElementId;
  bounds: ElementTransform;
  connectableAnchors: AnchorSpec[];
}>;
```

连接线渲染器只关心端点、路径和样式，不直接关心文字、图片或图形内部细节。

## 后端校验建议

后端需要从“通用 CanvasElement”升级为可判别联合类型：

- `type = "text"` 时必须有 `content.text` 和 `style.fontSize`。
- `type = "shape"` 时必须有 `shape.kind`，不能把显示文字塞进 `name`。
- `type = "connector"` 时必须有 `connector.from` 和 `connector.to`。
- `connector` 引用的 `elementId` 必须存在于同一 Scene。
- `generated_asset.status = "ready"` 时必须有 `assetId` 或 `url`。
- `generated_asset.status != "ready"` 时必须有 `placeholderStyle`。
- `group.children` 中的元素必须存在，且不能形成循环引用。

## 命令设计调整

新增元素仍然使用 `ADD_ELEMENT`，但 payload 应接收结构化草稿：

```ts
type AddElementCommand = BaseCommand & {
  type: "ADD_ELEMENT";
  payload: {
    sceneId: SceneId;
    element: CanvasElementDraft;
  };
};
```

更新元素建议支持按分区 patch：

```ts
type ElementPatch = {
  transform?: Partial<ElementTransform>;
  layer?: Partial<ElementLayer>;
  content?: Record<string, unknown>;
  style?: Record<string, unknown>;
  connector?: Partial<ConnectorElement["connector"]>;
  asset?: Partial<GeneratedAssetElement["asset"]>;
  subject?: Partial<GeneratedSubject>;
};
```

这样用户说“把箭头改成虚线”只改 `style.stroke.dash`；说“指向低糖标签”只改 `connector.to`；说“把人物换成微笑”只改 `subject.character.expression` 和生成提示词。

## 迁移策略

建议分三步迁移：

1. 兼容期：保留旧字段，同时新增 `transform`、`content`、`style`、`connector`、`asset` 等结构化字段。前端优先读取新字段，旧字段作为降级。
2. 适配期：后端命令执行器在写入时统一生成新结构，读取旧项目时自动转换。
3. 收敛期：测试覆盖完成后，移除旧的顶层 `x/y/width/height/text/shape/from/to` 写法。

旧元素转换示例：

```ts
function migrateElement(oldElement: LegacyCanvasElement): CanvasElement {
  return {
    ...oldElement,
    transform: {
      x: oldElement.x,
      y: oldElement.y,
      width: oldElement.width,
      height: oldElement.height,
      rotation: oldElement.rotation,
      opacity: oldElement.opacity,
      visible: oldElement.visible,
      locked: oldElement.locked
    },
    layer: {
      zIndex: oldElement.zIndex
    }
  };
}
```

## 本轮实现状态

当前代码已经完成兼容期升级：

- 后端 `CanvasElement` 支持 `transform`、`layer`、`content`、`connector`、`asset`、`subject`、`children`、`group` 等结构化字段。
- 后端仍保留 `x/y/width/height/zIndex/text/shape/from/to/connectorType/placeholderStyle` 等旧字段读取和输出能力，避免破坏现有 Demo。
- `text`、`shape`、`connector`、`generated_asset`、`group` 已加入类型专属校验。
- Scene 级校验已覆盖 connector 引用和 group children 引用。
- 删除被 connector 引用的元素时，connector 会降级为 `unknown`，并用 `reason = "invalid_reference"` 记录失效原因。
- 前端已拆出文字、图形、图片、生成素材、组合、未知元素和连接线渲染器。
- 连接线已改为 SVG `ConnectorLayer`，通过元素布局索引和锚点计算 path 起止点。
- 对人物、猫、桌子等常见真实对象，后端会优先归一化为 `generated_asset`，前端会使用语义 SVG 插画降级渲染，避免退回通用矩形占位。
- 人物不再用“女生”作为默认 fallback，而是使用 `metadata.renderHint = "character"` 和 `metadata.renderVariant = "male" | "female" | "neutral"` 描述人物变体；前端统一走 `characterIllustrationSvg`，按 variant 选择发型、衣服和体态。
- 语义插画识别只使用结构化主体字段，例如 `metadata.renderHint`、`subject`、`name`、`content.alt`、`content.label`；前端不能用 prompt 场景描述决定主体，避免“女生在桌子旁边”被误画成桌子。

## 结论

前端画面质量差，根因是对象模型没有完整表达内容、样式、连接语义和素材状态。重构时不应该只在 CSS 上修补，而要先把元素定义拆清楚：公共属性负责身份和布局，内容属性负责显示内容，样式属性负责视觉表现，类型专属属性负责连接线、生成素材、组合等特殊行为。这样前端才能从“猜着画”变成“按语义渲染”。

## Render Catalog 能力目录

本轮新增 `frontend/src/prototype/render-catalog.json` 作为“前端现在到底能直接画什么”的能力目录。它不是素材包本身，而是能力声明：

- `renderKey`：稳定渲染键，例如 `character`、`cat`、`table`。
- `aliases`：用户和大模型可能使用的别名，例如“男生、男人、boy、male”都归一到 `character + male`。
- `variants`：同一类对象的变体，例如人物的 `male/female/neutral`。
- `directRender`：前端是否有本地 SVG renderer。`true` 才能直接画；`false` 只能显示 `generated_asset` 占位等待生成。
- `assetKind/subjectType`：后端写入 `asset.kind` 和 `subject` 时使用的结构化分类。

管理边界：

- 前端负责 renderer registry：哪些 `renderKey` 有本地绘制函数，例如 `characterIllustrationSvg`、`catIllustrationSvg`、`tableIllustrationSvg`。
- 后端负责语义归一化：把用户输入、LLM 输出或旧 shape 草稿按 Render Catalog 归一成 `generated_asset`，写入 `metadata.renderKey`、`metadata.renderVariant`、`metadata.renderMode`。
- LLM 只负责选择意图和结构化命令，不允许臆造前端能力。系统提示会注入 Render Catalog 的紧凑清单，告诉它哪些对象是 `direct`，哪些只能 `placeholder`。
- 对目录外对象，后端不做猜测映射，保留原始描述到 `asset.prompt`；前端也不猜成相近对象。

这解决了“画女生却画成桌子”“画男生却画成女生”的根因：前端不再从 `asset.prompt` 里抓场景词做主体判断，也不会把未知 `character` 默认成女生；只有明确的 `renderKey + variant` 或 catalog alias 命中时才本地绘制。

当前 Render Catalog 只解决“能力受控”和“不要乱画”的底座问题，还不能覆盖带货、探店、知识教程创作者的高频表达。后续应拆成独立小 PR 逐步补充 Creator Visual Kit：

- 带货视频包：主播、手部演示、产品包装、价格牌、优惠券、卖点标签、购物车、直播间 UI 占位。
- 探店视频包：店门头、招牌、吧台、餐桌、菜单、菜品、服务员、顾客、路线箭头。
- 知识教程包：讲师、白板、步骤卡、代码窗口、屏幕占位、流程节点、对比表、时间轴。
- 镜头语言包：远景、中景、近景、特写、俯拍、推近、拉远、转场说明。
- 布局模板包：三镜头带货、探店五段式、教程步骤式、问题-解决-转化式。

每个后续 PR 只新增一个小能力包或一个 renderer，并同步更新 Render Catalog、README 原创功能说明、测试和验收命令。未实现 renderer 的对象只允许设置 `directRender = false`，保持生成素材占位，不得映射到相近对象。
