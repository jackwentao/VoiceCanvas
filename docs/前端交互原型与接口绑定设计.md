# VoiceCanvas 前端交互原型与接口绑定设计

> 本文档定义 VoiceCanvas MVP 前端交互原型、页面区域职责、前后端接口绑定、事件流绑定和测试方式。文档与 `接口与数据模型设计.md`、`技术架构设计.md` 保持同一套模型：前端不直接修改 Project，所有写操作都进入 Orchestrator 或 CommandExecutor 链路。

## 当前实现对齐

截至 2026-06-14，前端原型已经从早期 Mock 面板升级为可联调后端的演示入口：

- 默认访问地址：`http://127.0.0.1:4178/index.html`。
- 默认后端地址：`http://127.0.0.1:8000`，可用 `?apiBaseUrl=` 覆盖。
- 页面启动会读取 `GET /api/projects/project_demo_voicecanvas`，语音或 Demo 指令会进入 `POST /api/orchestrations` 或 SSE 编排接口。
- 前端保留后端不可用时的本地降级链路，但可信 Project State 以后端返回为准。
- 当前 UI 已包含设置菜单、新建项目、载入项目、导出 JSON、导出图片、长期记忆管理、Token 用量展示和 MinIO Catalog 素材代理解析。
- 当前验证命令：`cd frontend && npm run test:prototype`。

## 原型入口

当前已提供静态交互原型：

```text
frontend/src/prototype/index.html
```

推荐通过项目内置静态服务打开，避免浏览器直接打开本地 module 脚本时出现 MIME 或跨源限制：

```powershell
cd frontend
npm run prototype
```

启动后访问：

```text
http://127.0.0.1:4178/index.html
```

原型不依赖前端构建工具，方便比赛期间快速演示和后续替换真实 API。

原型文件职责：

- `index.html`：页面结构，包含顶部项目栏、左侧画布历史区、中间结构化画布、右侧 AI 交互栏、设置菜单和长期记忆面板。
- `styles.css`：布局、响应式和画布元素视觉样式。
- `mock-data.js`：接口契约、组件绑定、指令链路和初始 Project 数据。
- `app.js`：模拟 Orchestrator、SSE 事件流、CommandExecutor 结果和 CanvasPatch 局部刷新。
- `voice-session.js`：持续语音创作会话控制器、浏览器语音识别适配器、语音播报适配器和澄清回答候选解析。

## 页面信息架构

页面固定三栏：

```text
顶部：项目标题、Demo 快捷指令、设置菜单
左侧：画布历史区
中间：结构化画布
右侧：AI 交互栏
```

### 顶部项目栏

职责：

- 展示项目标题、模式、镜头数量和当前状态。
- 保留 Demo 快捷指令，方便比赛演示。
- 提供设置菜单，承载项目级动作：新建项目、载入项目、导出 JSON、导出图片。

绑定接口：

```http
POST /api/projects
GET /api/projects
POST /api/projects/:projectId/export
```

约束：

- 项目级动作不直接写画布元素。
- 导出动作统一进入 `Exporter`，并以 `EXPORT_COMPLETED` Patch 或 `TurnSummary` 回传 UI。

### 左侧画布历史区

职责：

- 展示镜头列表。
- 展示最近操作历史。
- 展示撤销状态。
- 点击镜头时只发起 `SWITCH_SCENE` 命令，不直接改 Project。

绑定模型：

- `CanvasHistoryViewModel`
- `HistoryEntry[]`
- `CanvasPatch[]`

订阅事件：

- `CANVAS_PATCH_APPLIED`

后端接口：

```http
GET /api/projects/:projectId
GET /api/orchestrations/:sessionId/events
```

约束：

- 左侧历史区不能直接写 `Project.scenes`。
- 撤销、重做、切换镜头都必须转成命令。

### 中间结构化画布

职责：

- 渲染当前 `activeSceneId` 对应的 `Scene`。
- 根据 `CanvasElement` 类型渲染文本、形状、连接线和未知元素占位。
- 收到 `CanvasPatch` 后局部刷新。
- 展示当前镜头说明、旁白和时长。

绑定模型：

- `Project`
- `Scene`
- `CanvasElement[]`
- `CanvasPatch`

订阅事件：

- `CANVAS_PATCH_APPLIED`

后端接口：

```http
GET /api/projects/:projectId
GET /api/orchestrations/:sessionId/events
```

约束：

- 画布是 Project State 的投影，不是可信状态源。
- 拖拽、选择、删除、调层等后续交互也必须生成 `CanvasCommand`。
- 未知元素用 `UnknownElement` 渲染占位，不阻断创作。

### 右侧 AI 交互栏

职责：

- 提供“开始语音创作”按钮，用户首次点击用于进入持续语音模式和触发浏览器麦克风授权。
- 完成授权并进入语音创作模式后，最终转写自动提交给 Orchestrator，不要求用户再次点击发送。
- 语音创作模式内支持创建元素、修改元素、删除元素、撤销/重做、澄清回答、导出和结束创作。
- 系统语音播报期间暂停语音监听，避免把系统播报识别成用户命令。
- 系统播报结束后先播放短提示音，再恢复监听，提示用户可以继续说话。
- 语音入口会丢弃明显环境噪声和无意义填充词，例如“嗯”“啊”“咳嗽”“环境噪声”，不提交给 Orchestrator。
- 键盘快捷键使用 `Alt+V` 切换语音创作模式，仅作为开发和演示兜底入口。
- 承载语音转写文本。
- 启动一轮 Orchestrator 任务。
- 展示当前阶段、执行进度、澄清问题、本轮总结和运行事件。
- 展示本轮 Token 用量、累计 Token 用量，并提供清空累计入口。
- 支持语音回答或点击澄清选项恢复同一个任务。

绑定模型：

- `OrchestrationSession`
- `OrchestrationEvent`
- `PendingClarification`
- `TurnSummary`
- `TokenUsage`

订阅事件：

- `TRANSCRIPT_PARTIAL`
- `TRANSCRIPT_FINAL`
- `STAGE_CHANGED`
- `PROGRESS`
- `CLARIFICATION_REQUESTED`
- `TURN_SUMMARY`

Token 用量绑定：

- 后端在 `TURN_SUMMARY.summary.tokenUsage` 和最终响应 `summary.tokenUsage` 中返回本轮用量。
- 前端状态归并层按 `sessionId` 去重，避免 SSE 事件和最终响应重复累计。
- 累计值保存到浏览器 `localStorage`，只影响展示，不写回后端 Project State。

后端接口：

```http
POST /api/orchestrations
POST /api/orchestrations/:sessionId/resume
POST /api/orchestrations/:sessionId/cancel
GET /api/orchestrations/:sessionId/events
```

约束：

- 右侧 AI 栏不能直接修改画布。
- 用户输入只提交给 Orchestrator。
- 澄清回答必须带上 `sessionId`，恢复原任务上下文。
- 受浏览器麦克风权限安全策略限制，首次进入语音创作模式需要一次显式操作授权麦克风；从第一条绘图指令到作品导出结束，核心创作流程应保持语音闭环。

## 持续语音创作模式

前端将语音能力拆成独立适配层：

```text
BrowserSpeechRecognitionAdapter
  使用 SpeechRecognition / webkitSpeechRecognition 获取中文语音转写。

BrowserVoiceFeedbackAdapter
  使用 SpeechSynthesis 播报系统反馈，并用浏览器音频能力播放恢复监听提示音。

VoiceSessionController
  管理开始、持续监听、系统播报、播报后提示音、自动恢复监听和结束创作。

resolveClarificationOption
  在候选集合内解析“左边那个”“第二个”“大的那个”等澄清回答。
```

语音会话流程：

```text
用户点击“开始语音创作”
-> 浏览器麦克风授权
-> 系统播报“语音创作模式已开启”
-> 持续监听
-> 最终转写自动提交 POST /api/orchestrations
-> 如需澄清，下一句语音自动提交 POST /api/orchestrations/:sessionId/resume
-> 系统播报执行结果
-> 播报期间暂停监听，播报结束后播放提示音并自动恢复监听
-> 用户说“结束创作”后关闭语音会话
```

测试方式：

```powershell
cd frontend
npm run test:prototype
```

该测试使用 Mock 语音识别和 Mock 播报验证：

- 开始语音创作后进入持续监听。
- 最终转写自动提交。
- 播报期间不会保持语音监听，避免系统播报进入指令系统。
- 播报结束后播放提示音并自动恢复监听。
- 播报后自动保持监听。
- “结束创作”关闭会话。
- “左边那个”“第二个”等澄清回答能解析到候选元素。
- 环境噪声会在语音入口被丢弃，不进入后端指令系统。

## 关键交互链路

### 1. 创建三镜头分镜

用户输入：

```text
创建一个三镜头的珍珠奶茶带货分镜，主打低糖和新品上市。
```

前端调用：

```http
POST /api/orchestrations
Content-Type: application/json

{
  "projectId": "project_demo_voicecanvas",
  "userInput": "创建一个三镜头的珍珠奶茶带货分镜，主打低糖和新品上市。"
}
```

后端返回：

```json
{
  "sessionId": "session_xxx",
  "status": "RUNNING"
}
```

前端随后订阅：

```http
GET /api/orchestrations/session_xxx/events
Accept: text/event-stream
```

事件顺序：

```text
TRANSCRIPT_FINAL
STAGE_CHANGED: understanding
STAGE_CHANGED: planning
PROGRESS
STAGE_CHANGED: executing
CANVAS_PATCH_APPLIED
TURN_SUMMARY
```

写入命令：

- `CREATE_SCENE`
- `ADD_ELEMENT`
- `SWITCH_SCENE`

### 2. 添加箭头

用户输入：

```text
给第二镜头加一个箭头，指向低糖标签，写上核心卖点。
```

写入命令：

- `SWITCH_SCENE`
- `ADD_ELEMENT`

关键绑定：

- `ADD_ELEMENT.payload.element.type = "connector"`
- `from.elementId = "el_product_cup"`
- `to.elementId = "el_low_sugar_tag"`

画布只消费执行后的 `ELEMENT_ADDED` Patch。

### 3. 指代不清进入澄清

用户输入：

```text
把标题放上面。
```

当 Project 中存在多个标题候选时，Orchestrator 返回：

```ts
{
  type: "ASK_CLARIFICATION",
  question: "当前有主标题、低糖标签和优惠标签，你想移动哪一个？",
  expectedAnswerType: "element_selection",
  options: [...]
}
```

前端展示 `ClarificationCard`，点击选项后调用：

```http
POST /api/orchestrations/:sessionId/resume
Content-Type: application/json

{
  "answer": "el_title_hook"
}
```

恢复后执行：

- `SWITCH_SCENE`
- `UPDATE_ELEMENT`

### 4. 导出 JSON

用户输入：

```text
导出项目数据。
```

前端调用：

```http
POST /api/projects/:projectId/export
Content-Type: application/json

{
  "format": "json",
  "scope": "project"
}
```

执行结果以 `EXPORT_COMPLETED` Patch 和 `TURN_SUMMARY` 回到前端。

| 前端区域 | 读模型 | 写入口 | 订阅事件 | 后端接口 |
| --- | --- | --- | --- | --- |
| 画布历史区 | `CanvasHistoryViewModel`、`HistoryEntry[]` | `CanvasCommand` | `CANVAS_PATCH_APPLIED` | `GET /api/projects/:projectId` |

## Mock 到真实接口的替换策略

当前原型在 `app.js` 中本地模拟以下模块：

- `AIOrchestrator`
- `CommandExecutor`
- `OrchestrationEventBus`
- `CanvasPatchStream`
- `Exporter`

接入真实后端时，替换边界如下：

1. `beginSession(userInput)` 替换为 `POST /api/orchestrations`。
2. 当前后端同步返回 `project`、`patches`、`history`、`events` 和 `summary`，前端可先消费同步响应完成刷新。
3. `executeCommand(command)` 从前端移出，由后端 CommandExecutor 执行。
4. 前端只根据 `CANVAS_PATCH_APPLIED` 更新本地投影，或在关键节点重新拉取 `GET /api/projects/:projectId`。
5. 导出按钮改为调用 `POST /api/projects/:projectId/export`。
6. Token 用量从 `summary.tokenUsage` 进入右侧 AI 栏，不参与 Project State。
7. 后续接入 SSE 时，再将同步 `events` 替换为 `EventSource` 增量事件。

前端仍保留本地 reducer，用于把 Patch 应用到 Project 投影；但 reducer 只处理后端确认过的 Patch。

## 结构化元素渲染升级

> 本节记录当前原型画布渲染约定，优先级高于早期“按 CanvasElement 类型渲染文本、形状、连接线和未知元素占位”的简化说明。

### 渲染层级

画布渲染拆为四层：

- `BackgroundLayer`：由 Scene canvas background 驱动。
- `ElementLayer`：渲染 `text`、`shape`、`image`、`generated_asset`、`group`、`unknown`。
- `ConnectorLayer`：独立 SVG 层，渲染所有 `connector`。
- `SelectionLayer`：当前仍通过元素和 connector 的 `is-selected` 样式表达，后续可拆出拖拽手柄和锚点手柄。

### 元素渲染规则

- 前端优先读取 `transform` 和 `layer`，旧字段 `x/y/width/height/zIndex` 作为降级。
- `text` 优先读取 `content.text`，旧字段 `text` 作为降级。
- `shape` 只显示 `content.label`，不把 `name` 当画面内容。
- `image` 使用 `content.url` 渲染图片，无资源时显示 `alt/name` 占位。
- `generated_asset.status = "ready"` 且有 `content.url` 时渲染图片；否则按 `placeholderStyle` 渲染生成占位。
- `unknown` 用 `label/name` 和占位样式表达，适合失效连接线或暂不支持对象。

### 连接线渲染规则

- `connector` 不再用横条 DOM 表达，统一由 SVG `<path>` 渲染。
- 箭头头部使用 SVG `<marker>` 和 `marker-end`。
- 前端构建 `ElementLayoutIndex`，根据目标元素 `transform` 和 `anchor` 计算真实端点。
- `anchor = "auto"` 时，按两个元素中心点方向自动选择上下左右边。
- 当前支持 `straight`、`orthogonal` 和 `bezier` 路径，不做复杂避障。

后续引入前端框架后，应补充：

- 组件测试：React Testing Library 或同等工具。
- 交互测试：点击澄清选项后调用 resume 接口。
- E2E 测试：Playwright 验证创建分镜、流式更新、澄清恢复和导出。

## Render Catalog 与语义素材渲染

前端不再靠散落的关键词判断“这是不是女生/猫/桌子”。原型启动时加载：

```text
frontend/src/prototype/render-catalog.json
```

渲染流程：

1. `generated_asset` 先检查 `metadata.renderKey` 和 `metadata.renderVariant`。
2. 如果 `renderKey` 在 catalog 中，且 `directRender = true`，并且 renderer registry 中存在对应 renderer，前端才渲染 SVG 插画。
3. 如果 catalog 命中但 `directRender = false`，前端显示生成素材占位，不猜成其他对象。
4. 如果没有显式 `renderKey`，前端可以用 `subject.*.renderKey` 或 catalog aliases 做降级识别。
5. 前端禁止根据 `asset.prompt` 的场景描述决定主体，避免“女生在桌子旁边”被桌子词抢走主体。

当前 renderer registry：

- `character` -> `characterIllustrationSvg`，支持 `male/female/neutral`。
- `cat` -> `catIllustrationSvg`。
- `table` -> `tableIllustrationSvg`。

新增常见图形或对象时的顺序：

1. 先在 Render Catalog 增加 `renderKey`、别名、变体和 `directRender`。
2. 如果只是希望 LLM 识别但暂时不能本地画，设置 `directRender = false`。
3. 如果要本地画，再新增前端 renderer 并注册到 `getIllustrationRenderer`。
4. 后端测试补 `tests/test_render_catalog.py`，前端测试补 `tests/prototype/prototype-contract.test.mjs`。
