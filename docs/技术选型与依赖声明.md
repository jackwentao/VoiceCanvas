# VoiceCanvas 技术选型与依赖声明

> 本文档记录 VoiceCanvas MVP 阶段的技术选型、依赖用途、引入边界和测试手段。后续新增依赖时，应同步更新本文档，并说明依赖被哪一层使用、为什么不能用已有能力替代、如何验证。

## 当前收口状态

2026-11-17 新增独立的单镜头自由 SVG 入口，具体边界见 [单镜头创作](单镜头创作.md)。这一入口直接利用外部模型生成 SVG 和源码修改，不走旧图元目录或 LangGraph Planner；不将模型的构图与绘图能力作为项目原创。原有结构化分镜入口继续沿用下述架构。

人物与动作提示调整只影响初次生成的系统文本。实验采用同一外部模型做六次调用，原始请求、完整产物与失败记录见 [提示对照](experiments/subject-quality-20261117/README.md)；绘制内容由模型生成。比较图使用本机已有 Edge、Playwright 和 sharp 离线渲染，这些是实验工具，不进入产品运行链路。测试沿用单镜头适配器和应用服务的离线回归。

单镜头 Agent 默认加载项目内 `svg-illustration` 文字技能，精简改编自 SVG Creator（Apache-2.0）与 Vector Illustration（MIT）。这是第三方知识依赖，无新增 Python/npm 运行包；固定来源、原文和许可证见 [third_party/drawing-skills](../third_party/drawing-skills/README.md)。标准库 `importlib.resources` 负责读取随包资源，不执行上游脚本或安装依赖，不实现上游的视觉反馈循环。`VOICECANVAS_SHOT_DRAWING_SKILL=none` 回退为基础提示；配置损坏明确报错，模型失败仍保留原画。边界和 `test_drawing_skills.py` 测试命令见 [接入说明](绘图技能接入.md)。项目不将上游作画知识或外部模型画质表述为原创。

| 单镜头能力依赖 | 用途与边界 | 降级与测试 |
| --- | --- | --- |
| 外部 OpenAI-compatible 文本服务（验证目标 DeepSeek v4.1 Flash / CommandCode 端点） | 通过 `ShotGenerator` 端口生成完整 SVG 或局部源码替换；只在后端持有密钥 | 不回退为预设图；保留上一版、显示错误，由用户决定重试；httpx MockTransport 验证 SSE、截断、错误与源码修改 |

以下“截至 2026-06-14”内容描述原有入口，并非单镜头生成路径的限制。

截至 2026-06-14，当前主分支的实际选型如下：

- 前端仍是原生 HTML/CSS/JavaScript 原型，使用 Node.js 静态服务启动，不引入 React/Vite 作为运行时依赖。
- 后端使用 Python 3.11、uv、FastAPI、Pydantic、LangGraph、SQLite、MinIO SDK 和 OpenAI-compatible HTTP 适配器。
- Dockerfile 只封装后端 API；MinIO 建议用独立 Docker 容器启动；前端仍用 `npm run prototype` 验证。
- 七牛云 SDK 尚未接入，当前以 MinIO 验证私有桶素材读取和后端代理边界。
- 所有启动、MinIO、Docker 和测试命令以根目录 [README](../README.md) 为准。

## 选型结论

VoiceCanvas 采用前后端分离结构：

```text
frontend/  前端原型与后续正式前端
backend/   Python 可信后端、AI 编排、状态管理和外部服务适配
docs/      产品、架构、接口和工程说明
```

核心技术路线：

- 前端当前使用原生 HTML/CSS/JavaScript 静态原型，后续再迁移到 React + Vite + TypeScript。
- 后端使用 Python + uv + FastAPI + LangGraph + Pydantic。
- 后端作为 Project State 的可信状态源，所有写操作经过 CommandValidator 和 CommandExecutor。
- LangGraph 承载可恢复 AI 编排：计划、工具调用、命令执行、澄清等待、恢复继续和总结。
- 七牛云、LLM、ASR、导出服务均通过 adapters 接入，不进入领域层。
- 当前真实 LLM 使用 DeepSeek OpenAI-compatible API；模型能力只用于自然语言理解和结构化命令草稿生成，不能直接覆盖 Project State。

## 选型原则

- 可交付优先：比赛周期短，先保证稳定 Demo、清晰架构和可运行测试。
- 解耦优先：领域模型、命令执行、AI 编排、语音识别、存储、导出和 UI 分层隔离。
- 可测试优先：核心逻辑必须能脱离浏览器、真实 LLM、ASR 和七牛云 SDK 做测试。
- 渐进引入：当前没有真实使用的框架或 SDK 不提前安装。
- 可替换优先：外部能力通过端口抽象接入，Mock 与真实实现可替换。

## 后端模块边界

```text
backend/src/voicecanvas/
  api/               FastAPI 路由、请求响应、SSE 入口
  graph/             LangGraph 编排流程
  application/       CommandValidator、CommandExecutor、ToolRunner、Session 服务
  domain/            Pydantic 领域模型和纯业务规则
  adapters/          LLM、ASR、七牛云、导出、存储适配器
  infrastructure/    配置、日志、持久化、HTTP 客户端等基础设施
```

硬性约束：

- `domain/` 不依赖 FastAPI、LangGraph、七牛云 SDK、LLM SDK、浏览器 API。
- `application/` 可以依赖领域模型和端口接口，但不直接依赖具体 SDK。
- `graph/` 只负责编排流程，不直接修改 Project State。
- 写操作必须经过 `CommandValidator` 和 `CommandExecutor`。
- 外部 SDK 的错误必须在 adapters 层转换为项目内统一错误结构。

## MinIO 与七牛云接入声明

七牛云能力作为存储与素材分发适配器接入，不作为领域模型的一部分。
当前素材包优先使用 MinIO 保存统一风格带货素材；MinIO 与七牛云都只能作为 `AssetStorage` 的具体适配器存在，不进入领域层。

推荐端口：

```py
class AssetStorage(Protocol):
    async def upload(self, file: bytes, options: UploadOptions | None = None) -> AssetRef: ...
    async def get_url(self, asset_id: str) -> str: ...
    async def delete(self, asset_id: str) -> None: ...
```

MVP 顺序：

1. `LocalAssetStorage`：本地演示和测试使用，不依赖网络。
2. `MinioAssetStorage`：读取统一风格的带货素材包，通过后端代理 URL 给前端渲染。
3. `QiniuAssetStorage`：比赛展示真实上传、公开访问或云端素材存储时接入。
4. FastAPI 签发上传凭证：避免把密钥放到浏览器端。

MinIO 环境变量：

```powershell
VOICECANVAS_ASSET_PROVIDER=minio
VOICECANVAS_MINIO_ENDPOINT=127.0.0.1:9000
VOICECANVAS_MINIO_BUCKET=voicecanvas-assets
VOICECANVAS_MINIO_ACCESS_KEY=your-access-key
VOICECANVAS_MINIO_SECRET_KEY=your-secret-key
VOICECANVAS_MINIO_SECURE=false
VOICECANVAS_ASSET_PUBLIC_BASE_URL=http://127.0.0.1:9000/voicecanvas-assets
```

真实素材包下载、上传与启动前检查：

```powershell
cd backend
uv run --no-editable python scripts/download_real_catalog_assets.py --overwrite
uv run --no-editable python scripts/seed_minio_catalog.py --asset-root ".\data\real-assets"
uv run --no-editable python scripts/check_minio_catalog.py --strict
```

`download_real_catalog_assets.py` 使用 Python 标准库从 Google Noto Emoji 下载 8 个公开 PNG 主体素材，来源许可证为 Apache-2.0。素材会落到 `backend/data/real-assets`，并保持与 `render-catalog.json` 中 `assetPath` 完全一致的相对路径。

`seed_minio_catalog.py --asset-root` 复用已声明的 `minio` SDK，把真实素材写入私有桶。`check_minio_catalog.py --strict` 会逐个检查 Catalog 对象是否已存在；当 `VOICECANVAS_ASSET_PROVIDER=minio` 时，后端默认启动流程也会执行同一套检查，素材包未上传完整时直接阻止服务启动。`--generate-placeholders` 仅作为比赛现场兜底，正式演示素材以真实下载包为准。

素材路径约束：

- Render Catalog 只保存 `catalog/commerce/` 前缀下的对象路径。
- 前端通过 `GET /api/assets/catalog?path=<assetPath>` 获取后端代理 URL。
- 后端拒绝空路径、绝对路径、`..` 和非素材前缀路径。
- 后端启动前必须确认所有 Catalog 素材已传入 MinIO；仅本地调试可用 `VOICECANVAS_SKIP_MINIO_CATALOG_CHECK=true` 临时跳过。
- 如果 MinIO 不可用，接口返回明确错误，画布元素降级为占位展示。

## AI 与语音接入声明

AI 和 ASR 都通过端口抽象接入：

```py
class LLMClient(Protocol):
    async def generate_action(self, input: OrchestratorInput) -> AIAction: ...

class SpeechRecognizer(Protocol):
    async def transcribe(self, audio: bytes) -> SpeechRecognitionResult: ...
```

当前实现：

- `DemoCommandPlanner`：本地演示语料规划器，无网络依赖。
- `LLMCommandPlanner`：真实 LLM Planner，使用 Pydantic 校验模型输出，再用 `CommandValidator` 校验业务命令。
- `OpenAICompatibleLLMClient`：通过 `httpx` 调用 DeepSeek OpenAI-compatible API。
- `ReferentResolver`：本项目原创指代消解模块，用 scene 完整元素信息匹配“左边那个杯子”等表达，多候选时返回澄清列表。
- `ParallelToolResultBuffer`：本项目原创并行工具结果聚合模块，避免 LLM 在只看到部分工具结果时提前行动。

后续顺序：

1. `MockLLMClient`：固定输出 `PLAN_TASKS`、`EXECUTE_COMMANDS`、`ASK_CLARIFICATION` 等动作。
2. 前端 Mock 语音输入：稳定演示语音入口和澄清流程。
3. 将真实 LLM Planner 接入完整 LangGraph 可恢复循环。
4. 真实 ASR adapter：通过后端或前端能力接入，仍输出统一文本输入。

## 依赖变更流程

### 自由 SVG 分镜项目编排

不新增第三方依赖。复用 FastAPI/Pydantic 校验接口，Python 标准库 SQLite 在既有画面数据库中保存分镜元数据并原子提交新增画面。应用层通过 StoryboardRepository 端口隔离数据库；分镜命令路由不使用模型 SDK，模型只负责原有画面生成/修改。项目原创能力是独立画面历史的编排、结构撤销、版本冲突与删除确认协议。原单镜头接口保留，错误不降级成模板画面；无密钥可测试管理接口，生成仍需要既有模型配置。说明与测试见 `docs/分镜项目API.md`。

前端复用浏览器 Web Speech API（SpeechRecognition / speechSynthesis）及已有 VoiceSessionController，识别转写不是项目自研 ASR。持续语音适配器在执行和播报时暂停识别，完成后恢复；权限/录音设备不可用时停止会话，降级为文字指令。语音服务可用性与中文准确率由浏览器和服务决定。本次浏览器验收在适配器边界模拟最终转写，API、SQLite、页面和下载真实执行；生成器回放已有画面，不算新模型效果或真实录音测试。无新增产品依赖，详见 `docs/语音分镜管理.md`。

### 单镜头直接文字编辑

本功能没有新增第三方依赖。领域层使用 Python 标准库 ElementTree 重建选中的文本块，沿用 FastAPI/Pydantic 和 SQLite 的校验、版本提交与历史。浏览器原生 DOMParser、XMLSerializer、SVG getComputedTextLength/getBBox/getCTM、Intl.Segmenter 和 ResizeObserver 提供实际字体测量、坐标换算、组合字符换行与预览尺寸提示；这些能力不参与模型调用。浏览器可将服务端校验过的 SVG 放入隐藏 iframe 测量区，sandbox 禁止脚本，CSP 禁止外部资源；用户新文字只按文本节点写入，实际画面仍以 img 预览。

缺少 Intl.Segmenter 时以 Unicode 码点回退，复杂组合字符边界可能不如支持该 API 的浏览器可靠；当前验收使用 Edge。特殊字形/共享定义保留自然语言修改入口，未知气泡路径不强行改造。测量器不评估人物遮挡或审美，不保证跨系统字体一致；测试与使用边界见 `docs/单镜头创作.md`。自由绘图仍由模型提供，本项目原创部分是文字块识别、受限编辑协议、确定性排版、溢出提示及版本闭环。

### 单镜头视觉反馈实验工具（2026-11-17）

`docs/experiments/visual-review-20261117/` 是离线保存的真实实验记录，产品运行不读取此目录。实验复用本机已有的 Playwright（控制 Edge 栅格化 SVG）、Microsoft Edge（实际渲染）、sharp（裁切、放大与合成对照），没有下载安装工具或增加产品依赖。这些工具负责图像处理，不提供审美评判或生图能力；第三方模型负责视觉描述和 SVG 补丁，项目负责流程编排、源码校验和结果留档。实际图片、调用成本、误判与复现方式见该目录 README。缺少实验工具时可直接在浏览器打开留存 SVG，既有单镜头入口继续使用人工预览。

`docs/experiments/storyboard-text-20261117/` 沿用上述实验工具检查正常分镜中的文字。`backend/tests/test_storyboard_text_replay.py` 复用产品已声明的 pytest、httpx MockTransport、应用服务和 SQLite 仓储进行无网络响应回放，不新增依赖，也不修改产品数据库；它验证文案保留、局部修改、重载与撤销重做，不对字体跨系统一致性或视觉美观作保证。

新增依赖前需要回答：

1. 这个依赖服务哪个模块？
2. 是否会进入 `domain/` 或污染核心模型？
3. 是否能通过端口隔离？
4. 是否有 Mock 或本地降级方案？
5. 是否需要新增测试？
6. 是否会影响比赛现场离线演示？

变更后必须同步：

- 更新 `frontend/package.json` 或 `backend/pyproject.toml`。
- 更新对应锁文件：`frontend/package-lock.json` 或 `backend/uv.lock`。
- 更新本文档依赖表。
- 在 PR 或提交说明中写明验证命令。


## 工作台改造的依赖与边界

- 本轮保持原生 HTML/CSS/JavaScript，不新增 npm/Python 第三方依赖。
- `workspace-controller.js` 只编排请求和展示状态；`canvas-renderer.js` 只投影后端元素；
  `file-download.js` 只下载后端结果或执行后端允许的 PNG 展示转换。
- 浏览器原生 SpeechRecognition、SpeechSynthesis 只作为输入输出适配器；不判断业务指令。
- 原生 `<dialog>`、键盘焦点、ResizeObserver、SVG/Canvas 属于浏览器能力，不是原创底层实现。
- 原生 Node 测试覆盖断流、失败、重复提交、澄清透传、导出与展示边界；后端 pytest 验证
  固定动作、SQLite 状态及重启恢复。没有接入或依赖 tldraw、Canva、Linear、XState 等服务或 SDK。
- 后端语义目录统一存储在 `backend/src/voicecanvas/resources/render-catalog.json`，后端部署
  不再读取前端源码目录；前端通过后端接口读取展示配置。

## 手绘首页

- 无新增运行依赖或外部字体；中文手写感使用系统楷体优先的字体栈，不支持时使用系统回退字体。
- 六幅展示画为本项目原创 SVG，存储于后端 `resources/showcase/`，不是外部平台素材，
  也不表示项目具备任意插画生成能力。原生 SVG 滤镜和 CSS 用于纸张、铅笔与拼贴效果。
- `ShowcaseCatalog` 维护分类与资源白名单；前端仅通过 `GET /api/showcase` 及其作品接口
  展示，不能修改展示目录。用户项目仍由既有项目 API 创建与保存。
- 原生 `<dialog>` 管理作品预览、焦点与 Escape 关闭；连接失败显示错误并支持显式重试。
- 开发验收使用环境中已有 Playwright 运行独立无界面浏览器，未加入项目运行依赖；
  可复现的 Node 状态测试和 pytest API 测试不依赖浏览器或外部服务。
