# VoiceCanvas 比赛冲刺行动计划

> 目标：在 2026 年 6 月 14 日 23:59 前提交一个稳定、可解释、可演示的 AI 语音绘图工具作品。本文档用于统一接下来的行动方向和验收标准。

## 总目标

比赛不是只看功能数量，而是看作品是否能清楚证明：

1. 用户可以不依赖鼠标键盘完成核心绘图创作。
2. 语音输入可以转化为可编辑的结构化画布，而不是一次性生成不可控图片。
3. 系统架构清晰，核心模块解耦，并且有可运行测试。
4. Demo 视频能稳定展示完整链路，评审可以快速理解创新点和完成度。

因此接下来优先级只有一个：先做出稳定可演示闭环，再扩展亮点。

## MVP 过关闭环

必须稳定跑通以下路径：

```text
用户语音输入
-> AI/Mock 编排器理解任务
-> 生成结构化画布命令
-> Command Validator 校验
-> Command Executor 执行
-> Project State 更新
-> Canvas Patch 推送给前端
-> 前端画布逐步更新
-> 历史区记录操作
-> AI 交互栏展示阶段、澄清和总结
-> 支持撤销
-> 支持导出 JSON 和图片
```

如果真实语音或真实 LLM 接入不稳定，Demo 可以使用浏览器语音识别或可控 Mock 编排兜底，但用户看到的主流程必须像真实语音创作工具一样运转。

## 优先级

### P0：必须完成

- 后端 Command Validator：校验命令字段、目标镜头、目标元素、坐标、尺寸、颜色和风险操作。
- 后端 Command Executor：支持创建镜头、切换镜头、新增元素、修改元素、删除元素、撤销、重做。
- 后端 Project State：作为唯一可信状态，不能由 AI 直接覆盖完整项目 JSON。
- 后端 History Manager：记录操作历史，支持撤销和重做。
- 后端 Orchestration Session：支持 `RUNNING`、`WAITING_FOR_USER`、`COMPLETED`、`FAILED`，能保存澄清上下文并恢复执行。
- 后端 Orchestration Events：输出阶段、进度、画布 Patch、澄清问题、本轮总结。
- 前端结构化画布：能根据元素列表渲染文字、形状、图片占位、箭头或连接线。
- 前端 AI 交互栏：展示语音转写草稿、当前阶段、澄清选项、执行总结。
- 前端历史区：展示镜头列表、操作历史、撤销重做状态。
- 导出：至少支持 JSON 导出和浏览器端图片导出。
- README：提供运行方式、测试方式、Demo 路径和未完成说明。
- 设计文档：明确计划支持、最终实现、未完成原因。
- Demo 视频：展示纯语音创建、修改、撤销、导出。

### P1：强加分

- 真实 LLM 接入，并保留 Mock 编排兜底。
- 浏览器语音识别接入，支持转写后人工确认发送。
- 用户长期记忆：保存并复用简单风格偏好，例如“清爽绿色”“带货三段式”。
- 七牛云对象存储适配器：用于上传导出文件或 Demo 素材，核心业务层只依赖存储接口。
- 流式更新体验：创建三镜头分镜时每个镜头逐步出现，而不是最后一次性刷新。

### P2：时间充足再做

- 更复杂的自然语言多轮编辑。
- 元素级 AI 生图。
- 丰富模板库。
- Playwright 端到端自动化。
- 更完整的用户记忆管理界面。

## 接下来行动顺序

1. 锁定 Demo 脚本和验收语料。
   - 先确定评审会看到的 3 分钟路径，不再无限扩需求。
   - 语料至少覆盖创建三镜头、添加元素、修改元素、箭头关系、澄清、撤销、导出。

2. 补齐后端确定性执行闭环。
   - 先实现命令校验、执行、历史、撤销重做和 Patch。
   - AI 编排先用 Mock 可控输出，确保主链路稳定。

3. 把前端原型接到真实后端状态。
   - 画布、历史区、AI 交互栏都从后端返回的事件和项目状态更新。
   - 前端不能直接改 Project State。

4. 补可恢复澄清流程。
   - 不明确目标元素时进入 `WAITING_FOR_USER`。
   - 用户回答后恢复原会话并继续执行。

5. 补导出和提交材料。
   - JSON 导出必须包含项目、镜头、元素、历史摘要。
   - 图片导出可以先基于当前画布 DOM 或 canvas 快照。
   - README 和设计文档同步最终实现与未完成原因。

6. 接入真实能力和加分项。
   - 真实 LLM、浏览器语音、七牛云存储都必须有开关或兜底。
   - 任何不稳定能力不能破坏 Demo 主链路。

7. 录制 Demo，做最终提交检查。
   - 录制前冻结 Demo 脚本。
   - 录制后用提交检查清单逐项确认仓库、视频、文档、测试和权限。

## 验收标准

### 产品验收

- 用户从空项目开始，能在 3 分钟内完成一个三镜头带货分镜草稿。
- 核心创作操作通过语音或语音转写输入触发，不依赖鼠标键盘直接绘图。
- 至少支持新增、修改、删除、切换镜头、撤销、导出。
- 至少支持文字、形状、图片占位、箭头或连接线四类画布元素。
- 遇到“把它放大”“改那个标题”等不明确指令时，系统能发起澄清，而不是静默失败。
- 未知元素能降级为语义占位元素，并在界面或总结中说明。

### 工程验收

- 后端领域层不依赖 FastAPI、LangGraph、LLM、ASR 或七牛云 SDK。
- 写操作统一经过 Command Validator 和 Command Executor。
- Project State 是唯一可信状态，Patch 只用于 UI 增量更新。
- 历史区和 AI 交互栏只订阅状态或事件，不直接改画布状态。
- 七牛云相关代码只存在于 adapter 或 infrastructure 层。
- 每个 P0 模块都有自动化测试或明确手动验证方式。
- `uv run --no-editable pytest` 通过。
- `uv run --no-editable ruff check .` 通过。
- `uv run --no-editable mypy src` 通过。
- `npm run test:prototype` 通过。

### Demo 验收

- Demo 视频能清楚展示“语音到可编辑分镜”的差异化，不像普通文生图。
- 视频中必须出现创建、修改、关系表达、澄清或容错、撤销、导出。
- 视频说明架构亮点：AI 负责理解和编排，系统负责确定性执行。
- 视频说明工程质量：模块解耦、测试覆盖、可恢复会话、可降级策略。
- 视频长度建议控制在 3 到 5 分钟，优先清晰稳定。

### 提交验收

- GitHub 仓库地址可访问。
- 2026 年 6 月 14 日 23:59 前完成作品提交。
- 2026 年 6 月 15 日 00:00 起确认仓库和 Demo 视频公开可访问。
- README 包含项目价值、运行方式、测试方式、Demo 说明和当前状态。
- 设计文档包含计划支持能力、最终实现能力、未完成原因。
- commit 历史有阶段性提交，不是最后一次性堆叠。
- PR 或 PR 记录能说明每个阶段的背景、改动、测试和风险。

## 当时间不够时的取舍规则

- 保主链路，不保功能数量。
- 保可演示稳定性，不保真实 AI 覆盖率。
- 保结构化可编辑画布，不保精美生成图。
- 保测试和文档，不保低优先级视觉细节。
- 保七牛云适配接口和一个可展示用例，不把核心业务绑死在七牛云 SDK 上。

当前缺口集中在：

- 历史、撤销、重做和 Patch。

- 导出、Demo 脚本和最终提交材料。
